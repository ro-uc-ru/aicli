# 001-aicli-new: `aicli new` command

- Status: approved
- Owner:  ro-uc-ru
- Date:   2026-10-13

## 1. Context

### Goal (required)
`aicli new <name>` generates the base skeleton of a FastAPI backend for AI/LLM apps, with the fixed folder structure of the project and a minimal service that starts and passes its own tests.

### Why (required)
It is the foundation for everything else: without a consistent skeleton there is nothing to evolve (models, repositories, LLM providers). It fixes the layout convention from day one instead of ad-hoc projects.

### Optional
- Users / Beneficiaries: data scientists and AI engineers starting a new backend.
- Definitions:
  - Base skeleton: the project generated by default, with no optional capability (LLM, vector store, queues, observability).
  - Valid name: starts with a lowercase letter, contains only lowercase letters, digits, hyphen (`-`) and underscore (`_`), is at most 255 characters long, and, once normalized as in PEP 503 (any run of `-` and `_` read as a single `-`), is not the name of any dependency declared in FR-007.
- Fixed skeleton layout (relative to `<name>/`, shown here with the example name `myapp`). This tree is the source of truth for the generated content; any layout change is made here:

```
myapp/
├── .env.example
├── .dockerignore          # see FR-025
├── .gitignore
├── README.md
├── Dockerfile             # minimal, see FR-017
├── docker-compose.yml     # services: {} (no services)
├── pyproject.toml         # name = <name>, deps (FR-007) + ruff config (FR-020)
├── alembic.ini
├── app/
│   ├── __init__.py
│   ├── main.py            # creates the FastAPI app, sets up logging, registers error handlers, mounts api/router.py
│   ├── config.py          # Settings (pydantic-settings, reads environment variables)
│   ├── logging.py         # stdlib logging setup, see FR-026
│   ├── errors.py          # global error handlers, see FR-027
│   ├── db.py              # SQLAlchemy declarative base + session
│   ├── api/
│   │   ├── __init__.py
│   │   ├── router.py      # aggregates the routers
│   │   └── routers/
│   │       ├── __init__.py
│   │       └── health.py  # GET /health -> 200 + HealthModel
│   ├── models/            # SQLAlchemy tables
│   │   └── __init__.py
│   ├── schemas/           # Pydantic input/output models
│   │   ├── __init__.py
│   │   ├── health.py      # HealthModel
│   │   └── errors.py      # ErrorModel
│   ├── repositories/      # data access
│   │   └── __init__.py
│   ├── services/          # business logic
│   │   └── __init__.py
│   └── ai/                # empty, agnostic to classic ML and LLM
│       └── __init__.py
├── migrations/            # Alembic, no revisions
│   ├── env.py
│   ├── script.py.mako
│   └── versions/
│       └── .gitkeep
└── tests/
    ├── __init__.py
    ├── conftest.py        # FastAPI test client
    ├── test_config.py     # default DATABASE_URL (FR-021), APP_NAME as app title, invalid LOG_LEVEL fails (EC-013), logging configured (FR-026)
    ├── test_health.py     # GET /health -> 200
    └── test_errors.py     # unknown route -> 404 ErrorModel; unhandled exception -> 500 ErrorModel
```

- Permitted Go dependencies (STK-6), only if needed: `golang.org/x/sys` (EC-010, atomic no-replace rename) and `golang.org/x/term` (TTY detection, FR-015). Neither is required by this spec if the standard library suffices.

- Designs (non-normative; FR/EC and golden files prevail): [`designs/success-output.md`](designs/success-output.md), the styled and plain output of FR-015; [`designs/error-output.md`](designs/error-output.md), the styled and plain output of FR-023.

- Layers: `api/routers` only receives and answers HTTP; business logic lives in `services/`; data access in `repositories/`; `models/` are the SQLAlchemy tables and `schemas/` the Pydantic input/output models. `ai/` is empty in the base skeleton; its content is defined by future specs.

## 2. Functional Requirements

- FR-001 (event-driven)  WHEN the user runs `aicli new <name>` with a valid name and a non-existent destination, the CLI shall create the directory `./<name>` with the fixed layout of the base skeleton and exit with code 0.
- FR-002 (ubiquitous)    The CLI shall generate exactly the tree of files and folders in the fixed layout (no additional files or folders) for every project, with no flag or configuration that alters it.
- FR-003 (ubiquitous)    The CLI shall generate the convention folders (`models`, `schemas`, `repositories`, `services`, `ai`, `api`, `api/routers`, `tests`, `migrations`) even when they contain no logic, each containing at least one file (`__init__.py` or `.gitkeep`) so that they exist on disk and in a git repository.
- FR-004 (ubiquitous)    The CLI shall generate a FastAPI app that mounts the routers from `api/router.py` and exposes `GET /health`, defined in `api/routers/health.py`, returning status 200 and a JSON body built from `HealthModel` (defined in `schemas/health.py`) with one field, `status: int`, whose value is 200.
- FR-005 (ubiquitous)    The CLI shall generate the app configuration with pydantic-settings reading environment variables, with exactly three settings: `APP_NAME` (default value: `<name>`), `DATABASE_URL` (default `sqlite:///./app.db`, defined in `Settings`, not only in `.env.example`) and `LOG_LEVEL` (one of `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`; default `INFO`), read from environment variables and from a `.env` file in the working directory (real environment variables take precedence). `APP_NAME` is the title of the FastAPI app (`info.title` in `/openapi.json`).
- FR-006 (ubiquitous)    The CLI shall generate SQLAlchemy (declarative base and session) and Alembic configured with no initial revisions.
- FR-007 (ubiquitous)    The CLI shall generate a uv-managed `pyproject.toml` with `name` set to `<name>`, declaring `requires-python = ">=3.12"`, the runtime dependencies `fastapi`, `uvicorn`, `sqlalchemy`, `alembic` and `pydantic-settings`, and a `dev` dependency group (`[dependency-groups]`) with `pytest`, `httpx` and `ruff`, each with a lower-bound version (`>=`) and no other dependency.
- FR-008 (ubiquitous)    The CLI shall generate pytest tests that pass unmodified, without network access and without calling any LLM provider.
- FR-009 (ubiquitous)    The CLI shall generate `.env.example` with the variables `APP_NAME`, `DATABASE_URL` and `LOG_LEVEL` and a `.gitignore` that excludes `.env`, `*.db`, Python artifacts (`.venv/`, `__pycache__/`, `*.py[cod]`, `*.egg-info/`, `build/`, `dist/`), tool caches and reports (`.pytest_cache/`, `.ruff_cache/`, `.coverage`, `htmlcov/`), editor, OS and AI-agent files (`.idea/`, `.vscode/`, `.DS_Store`, `.agents/`, `.claude/`, `.mcp.json`), and shall never exclude `.env.example` or `uv.lock`; the CLI shall never generate a `.env`.
- FR-010 (ubiquitous)    The CLI shall generate a `README.md` with the commands to install (`uv sync`), run (`uv run uvicorn app.main:app --reload`), test (`uv run pytest`) and lint (`uv run ruff check .`) the project.
- FR-011 (ubiquitous)    The CLI shall exclude from the base skeleton any optional capability (LLM provider, vector store, queues, observability).
- FR-012 (unwanted)      IF the name is not provided, THEN the CLI shall exit with code 1, write to stderr an error stating that the name is missing, and create no files.
- FR-013 (unwanted)      IF the name is not valid, THEN the CLI shall exit with code 1, write the reason to stderr, and create no files.
- FR-014 (unwanted)      IF the destination `./<name>` already exists, THEN the CLI shall exit with code 1, write an error to stderr, and modify no existing file.
- FR-015 (event-driven)  WHEN the project is created successfully, the CLI shall print to stdout exactly this plain text, with `<name>` substituted, without running any of the steps and without spawning any external process:
  ```
  Created project <name>

  Next steps:
    cd <name>
    cp .env.example .env   (optional)
    uv sync
    uv run uvicorn app.main:app --reload
  ```
  When stdout is a TTY, `NO_COLOR` is unset or empty and `TERM` is not `dumb`, the output shall be styled with Lipgloss (e.g. emphasized first line, highlighted commands, dimmed `(optional)`); styling may only add ANSI sequences and a `✓ ` prefix on the first line, so that stripping both yields exactly the plain text above. Otherwise the output shall be the plain text with no ANSI sequences.
- FR-016 (unwanted)      IF writing any file fails, THEN the CLI shall exit with code 1, write the error with context to stderr, and remove everything it created in that run, so that `./<name>` exists only when the project is complete.
- FR-017 (ubiquitous)    The CLI shall generate a fixed, minimal `Dockerfile` (base `python:3.12-slim`, `uv` binary copied from the official `ghcr.io/astral-sh/uv` image, dependencies installed with `uv sync --no-dev`, non-root user, start command `uvicorn app.main:app` on `0.0.0.0:8000`), with no variants or options.
- FR-018 (ubiquitous)    The CLI shall generate a `docker-compose.yml` whose entire content is `services: {}`.
- FR-019 (ubiquitous)    The CLI shall generate `app/ai/` containing only an empty `__init__.py`.
- FR-020 (ubiquitous)    The CLI shall generate the `ruff` configuration in `pyproject.toml` so that the generated project passes `uv run ruff check .` unmodified.
- FR-021 (ubiquitous)    The CLI shall generate the default `DATABASE_URL` as `sqlite:///./app.db`, and Alembic's `migrations/env.py` shall read the database URL from `Settings`.
- FR-022 (ubiquitous)    The CLI shall produce byte-for-byte identical output (content and file permissions) for the same name on every run, with nothing date-dependent or random. Permissions are set explicitly and do not depend on the user's umask: `0644` for files and `0755` for directories.
- FR-023 (unwanted)      IF the command fails for any reason, THEN the CLI shall exit with code 1, leave stdout empty, and write the error to stderr. The plain message starts with `Error: ` and may be followed by continuation lines indented by two spaces (e.g. `  Usage: aicli new <name>`). When stderr is a TTY, `NO_COLOR` is unset or empty and `TERM` is not `dumb`, the message shall be styled with Lipgloss (e.g. red bold `Error:`, dimmed continuation lines); styling may only add ANSI sequences and a `✗ ` prefix on the first line, so that stripping both yields exactly the plain message. Otherwise the message shall be plain with no ANSI sequences. The only exception is interruption by a signal (EC-009), which exits with 128 plus the signal number and prints nothing.
- FR-024 (unwanted)      IF more than one positional argument is given, THEN the CLI shall exit with code 1, write a usage error to stderr, and create no files.
- FR-025 (ubiquitous)    The CLI shall generate a `.dockerignore` that excludes `.git`, `.env`, `*.db`, the same Python artifacts, tool caches and reports, and editor, OS and AI-agent files listed in FR-009 (but not `uv.lock`), so that secrets and local artifacts never enter the image.
- FR-026 (ubiquitous)    The CLI shall generate `app/logging.py`, called at app startup, that configures standard-library `logging` at the level given by `LOG_LEVEL` with one fixed format, and the generated code shall never log `DATABASE_URL` or any other secret (ERR-4).
- FR-027 (ubiquitous)    The CLI shall generate `app/errors.py`, registered in `app/main.py`, so that every error response (HTTP errors, request validation errors and unhandled exceptions) has the same JSON body built from `ErrorModel` (defined in `schemas/errors.py`) with the fields `status: int` (the HTTP status code) and `message: str`, where `message` is the fixed literal of that status: 404 `Not Found`, 405 `Method Not Allowed`, 422 `Unprocessable Entity`, 500 `Internal Server Error`; any other status uses its standard reason phrase.

## 3. Edge Cases

- EC-001 IF the name contains path separators or `..` segments (e.g. `../x`, `a/b`), THEN the CLI shall reject it as invalid and write nothing outside the working directory. (FR-013)
- EC-002 IF the name starts with a digit, hyphen or dot, or contains uppercase letters, spaces or non-ASCII characters, THEN the CLI shall reject it as invalid. (FR-013)
- EC-003 IF the name is an empty string (`aicli new ""`), THEN the CLI shall treat it as a missing name. (FR-012)
- EC-004 IF the destination exists as a regular file or as an empty directory, THEN the CLI shall treat it like any existing destination and leave it untouched. (FR-014)
- EC-005 IF the working directory is not writable, THEN the CLI shall exit with code 1 and write the error to stderr. (FR-016)
- EC-006 WHEN the command runs without a TTY, the CLI shall generate the same files and exit with the same code as with a TTY. (FR-001)
- EC-007 WHEN it runs twice in a row with the same name, the CLI shall fail on the second run with the existing-destination error and leave the result of the first run intact. (FR-014)
- EC-008 IF the destination exists as a symbolic link (including a broken one), THEN the CLI shall treat it like any existing destination and leave it untouched. (FR-014)
- EC-009 IF the process receives SIGINT or SIGTERM at any point while generating, THEN the CLI shall leave no `./<name>` and no temporary artifact, and exit with code 130 (SIGINT) or 143 (SIGTERM). (FR-016)
- EC-010 IF two runs with the same name execute at the same time, THEN exactly one shall succeed; the other shall fail as in FR-014, and the CLI shall never replace a destination that appeared after its initial check, even an empty directory. (FR-014)
- EC-011 IF the name equals a dependency declared in FR-007, in any spelling that normalizes to it (e.g. `fastapi`, `pydantic_settings`, `pydantic__settings`), THEN the CLI shall reject it as invalid. (FR-013)
- EC-012 IF the name is longer than 255 characters, THEN the CLI shall reject it as invalid; no artifact the CLI creates during the run shall have a name whose length depends on `<name>`. (FR-013)
- EC-013 IF `LOG_LEVEL` is not one of the allowed values, THEN the generated app shall fail at startup with a validation error naming the setting. (FR-005)
- EC-014 IF a route of the generated app raises an unhandled exception, THEN the response shall be status 500 with an `ErrorModel` whose `message` is `Internal Server Error` (no traceback, exception text or secrets), and the only thing the generated app code logs is the exception's type name, with no message, traceback or request data, so that nothing sensitive is logged by it (logs written by the server itself are out of scope). (FR-027, FR-026)

## 4. Scope

### In scope
- Non-interactive `aicli new <name>` command with exactly one positional argument; zero arguments is FR-012 and more than one is FR-024.
- Name validation at the command boundary.
- Complete, fixed base skeleton (app, config, logging, error handling, DB, migrations, tests, minimal docs, Dockerfile and empty compose).

### Out of scope
- Interactive mode (name prompt): there is none in this spec; it will be handled in another spec.
- Choosing a database other than SQLite: a future spec (STK-4 for drivers).
- `git init` and `uv sync`: the CLI spawns no external processes in this spec; the user runs them following the printed steps.
- Flag to overwrite or generate into a non-empty directory: an existing destination is always an error.
- Destination directory other than `./<name>`: no convention requires it yet.
- Optional capabilities (LLM, vector store, queues, observability): opt-in features of future specs (STK-5).
- Later generators (`generate model`, migrations): their own specs.
- `docker-compose.yml` services (DB, etc.): added in later specs; choosing a DB implies deciding drivers (STK-4).
- Deploying or hosting the image: out of scope per SCP-3; the Dockerfile only packages.
- Authentication and authorization (API key, JWT, OAuth): opt-in feature of a future spec (STK-4, STK-5); `api/router.py` is where it will hook in.
- Observability beyond standard-library logging (traces, metrics): opt-in, future spec (STK-5).
- Windows support: not supported yet (LIM-1).

- [x] Go test: the generated tree matches exactly the fixed layout (no missing or extra files)
- [x] Golden files of the generated skeleton reviewed and versioned (TST-2)
- [x] Golden file of the plain success output; a test checks that the styled output, with ANSI and the `✓ ` prefix stripped, equals it (FR-015)
- [x] Integration test: a project is scaffolded into a temp dir and its own pytest and `ruff` pass (TST-3, TST-5)
- [x] Integration test: in the scaffolded project, `uv run alembic upgrade head` exits 0 using the default SQLite URL, without network (FR-006, FR-021)
- [x] Golden file of the plain error output; a test checks that the styled error, with ANSI and the `✗ ` prefix stripped, equals the plain one, and that stdout stays empty (FR-023)
- [x] The `Dockerfile` is verified only by its golden file; no test builds the image (FR-017)
- [x] Paths are built only with `path/filepath` and no shell is spawned (ARC-8); tests run on macOS and Linux (LIM-1)
- [x] No test calls LLM providers; only the integration test uses the network, solely to install dependencies (TST-6)
- [x] `go test ./...` and `golangci-lint run` pass (TST-4)
